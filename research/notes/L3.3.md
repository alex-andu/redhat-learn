# Research — L3.3 Execuție condiționată: if, test, [ ]

**Obiectiv oficial:** C3-1 „Conditionally execute code (use of: if, test, [], etc.)”.
**Stare cercetare:** parțială. Citit (2026-11-16): GNU Bash Manual „Bash Conditional Expressions” (teste de fișier, șir, întreg — liste confirmate: `-e -f -d -r -w -x -s -L -z -n`, `= == !=`, `-eq -ne -lt -le -gt -ge`; în `[[` partea dreaptă a `==` e tipar). „Conditional Constructs” → 429 (necitit); sintaxa if/elif/else/fi, `case`, `&&`/`||` din bash(1) (SHELL GRAMMAR).

## Afirmații-cheie
- `if COMANDĂ; then …; elif …; else …; fi`: condiția este orice comandă; exit status 0 = adevărat.
- `[` este comandă (builtin) sinonimă cu `test`; ultimul argument trebuie să fie `]`; spațiile din jurul parantezelor sunt obligatorii.
- `[[ ]]` este cuvânt rezervat bash; nu face word splitting pe variabile, acceptă `==` cu tipare, `&&`, `||`.
- Șir: `=` (POSIX), `!=`, `-z`, `-n`; întreg: `-eq -ne -lt -le -gt -ge`; fișier: vezi mai sus.
- `&&` rulează a doua comandă doar dacă prima are status 0; `||` doar dacă nenul.
- `case VAR in tipar) …;; esac`.
- `$?` în condiții; `exit` cu coduri.

## Comenzi
`test`, `[ ]`, `[[ ]]`, `if/elif/else/fi`, `case`, `&&`, `||`, `!`, `id -u`, `grep -q`.

## Nesigurante
Mesajele de eroare (`[: missing ']'`, `integer expression expected`) sunt reconstituite din comportament cunoscut, nu capturate.
