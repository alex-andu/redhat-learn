# Research — L4.5 Prioritatea proceselor (nice)

**Obiectiv oficial:** C4-5 „Adjust process scheduling”.
**Stare cercetare:** parțială. docs.redhat.com (RHEL 10: „Tuning scheduling policy”, `optimize-tuning_scheduling_policy`) → HTTP 403, necitit. Surse: `nice(1)`, `renice(1)`, `ps(1)`, `top(1)`, `sched(7)`, `chrt(1)`, `taskset(1)` — din cunoștințe, nerecitite în sesiune.

## Afirmații-cheie
- Valoarea „nice” (NI) merge de la -20 (cea mai mare prioritate) la +19 (cea mai mică); implicit 0 pentru comenzile pornite normal; un proces copil moștenește nice-ul părintelui.
- `nice -n N comandă` pornește o comandă cu nice-ul 0+N (N implicit 10 dacă lipsește `-n`); `nice` fără argumente afișează nice-ul curent. `nice -n -5 comandă` (doar root).
- `renice -n N -p PID` schimbă nice-ul unui proces existent (forma veche `renice N PID` încă acceptată); `-u utilizator`, `-g grup`.
- Utilizatorii obișnuiți pot doar crește nice-ul (scad prioritatea) proceselor lor; scăderea nice-ului sau valorile negative cer root (în mod implicit, fără RLIMIT_NICE).
- `ps -o pid,ni,pri,cmd`; în `top`, coloanele PR și NI; tasta `r` = renice. PR pentru procese normale este 20 + NI (top(1)).
- Nice nu limitează CPU: contează doar când procesele concurează pentru același CPU; este o pondere relativă.
- Politici de planificare (sched(7)): SCHED_OTHER (implicită, folosește nice), SCHED_FIFO/RR (timp real, `chrt`) — doar menționate (Deep dive).
- `taskset -c 0 comandă` fixează comanda pe CPU 0 (util pentru a demonstra concurența).

## Comenzi
`nice`, `nice -n`, `renice -n -p`, `renice -n -u`, `ps -o pid,ni,pri,cmd`, `top` (r), `taskset -c`, `chrt -p` (menționat).
