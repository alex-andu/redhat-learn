**Obiective oficiale:** C8-4 „Restrict network access using firewalld and firewall-cmd”; C10-1 „Configure firewall settings using firewall-cmd/firewalld”.
**Stare cercetare:** parțială. docs.redhat.com (`secure-using_and_configuring_firewalld`) → HTTP 403 la 2026-11-16, NECITIT. Nimic rulat pe RHEL 10.

## Afirmații verificate în sursă
- Fără `--permanent`, schimbarea afectează doar configurația runtime; cu `--permanent`, e salvată dar „nu are efect imediat, doar după restart/reload/reboot”. Pentru efect imediat + persistență: comanda se rulează și fără, și cu `--permanent`.
- `--reload`: „configurația permanentă curentă devine noua configurație runtime” — modificările doar runtime nesalvate se pierd; păstrează starea (conexiunile active).
- `--complete-reload`: reîncarcă tot, inclusiv modulele netfilter; „va întrerupe probabil conexiunile active”; doar pentru probleme grave.
- `--runtime-to-permanent`: salvează configurația runtime activă peste cea permanentă.
- `--check-config`: validează configurația permanentă (XML și semantică).
- `--state`: dacă daemonul rulează (exit 0 dacă e activ).
- `--get-default-zone` / `--set-default-zone=ZONE` (schimbare runtime și permanentă); `--get-active-zones` (zone cu legătură la interfață sau sursă); `--get-zones`; `--list-all [--zone=Z]`; `--change-interface=IFACE` (echivalent remove + add; ca add dacă nelegată).
- `--add-service` / `--remove-service` (repetabile); `--get-services` (servicii predefinite); `--list-services`; `--add-port` / `--remove-port=PORT[-PORT]/PROTO` (tcp, udp, sctp, dccp); `--add-source=SOURCE` (adresă, MAC, ipset).
- `--add-rich-rule='REGULĂ'`; `--timeout=TIMEVAL` (secunde sau număr + s/m/h) face regula temporară; **nu se combină cu `--permanent`**.
- Zone predefinite (de la cel mai puțin la cel mai de încredere): drop (pachete aruncate fără răspuns, doar conexiuni de ieșire), block (refuzate cu mesaj prohibited), public („doar conexiunile selectate sunt acceptate”), external (cu mascare IPv4), dmz, work, home, internal, trusted („toate conexiunile acceptate”).

## Din cunoștințe, necitit (de confirmat pe RHEL 10)
- Pachet `firewalld`, serviciu `firewalld.service`; backend nftables (de la firewalld 0.6+/RHEL 8; RHEL 10: nftables; `iptables` legacy nu mai e backend).
- Zona implicită pe RHEL: `public`; servicii permise implicit în `public`: `ssh`, `dhcpv6-client` (posibil și `cockpit` în unele instalări).
- Definiții de servicii: `/usr/lib/firewalld/services/*.xml` (valori implicite, nu se editează); suprascrieri în `/etc/firewalld/services/`. Configurația permanentă: `/etc/firewalld/` (`firewalld.conf`, `zones/*.xml`). `firewall-cmd --permanent` modifică `/etc/firewalld/zones/<zonă>.xml`.
- Opțiuni utile: `--get-services | tr ' ' '\n' | grep`, `--info-service=NAME` (porturi ale unui serviciu), `--query-service=NAME` (yes/no, exit code), `--query-port=`, `--zone=ZONE` (explicit), `--remove-interface`, `--list-ports`, `--list-sources`, `--list-rich-rules`.
- `firewall-cmd --add-port=8080/tcp` fără `--permanent` dispare la reload/reboot — capcană de examen clasică.
- Moduri: `firewall-cmd --panic-on/--panic-off` (blochează tot traficul) — atenție la SSH.
- Interfața legată la o zonă este gestionată implicit de NetworkManager prin `connection.zone` (`nmcli con mod ID connection.zone ZONĂ`) — de confirmat.
- Porturi SELinux (C10) și firewall sunt straturi independente: un serviciu pe port neobișnuit cere ambele.
- Exemple de rich rule uzuale: `rule family="ipv4" source address="192.0.2.0/24" service name="ssh" accept` (sintaxă din cunoștințe; pagina richlanguage necitită).
- ICMP/ping: tratat prin tipuri icmp; nu e în obiectiv.
- Platforma nu execută comenzi; „blocarea SSH” din laborator doar pe VM de test, cu acces la consolă.
