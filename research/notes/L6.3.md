# Research — L6.3 NFS: montare și demontare

**Obiectiv oficial:** C6-2 „Mount and unmount network file systems using NFS”.
**Stare cercetare:** parțială. docs.redhat.com (RHEL 10) → HTTP 403 la 2026-11-16 (`managing_file_systems/mounting-nfs-shares` necitit). Citite efectiv (man7.org, 2026-11-16): `nfs(5)`, `exports(5)`, `showmount(8)`, `mount(8)`, `umount(8)`. Nimic rulat pe RHEL 10.

## Afirmații verificate în sursă
- Linia fstab NFS: `server:/export  /mnt  nfs  defaults  0 0`; ultimele două câmpuri nu sunt folosite de NFS (convențional `0 0`). Pagina spune că folosirea tipului `nfs4` în fstab este **deprecată** (exemplele din pagină folosesc totuși și `nfs4` cu `sec=`).
- `hard` (implicit): cererile se reîncearcă la nesfârșit; `soft`: după `retrans` retransmisii eșuează cu EIO; `soft` „can cause silent data corruption in certain cases”.
- Versiune: `nfsvers=n` / `vers=n`; dacă serverul nu o suportă, montarea eșuează. Implicit clientul încearcă **4.2** apoi negociază în jos.
- `proto`: pentru NFSv4 valorile sunt tcp, tcp6, rdma, rdma6; implicit TCP.
- `rsize`/`wsize`: implicit negociate; maximum 1 048 576 B (1 MiB).
- `sec=`: listă separată prin `:` dintre none, sys, krb5, krb5i, krb5p.
- `fg` (implicit) vs `bg`; `timeo` în zecimi de secundă; `retrans` implicit 3 (UDP) / 2 (TCP).
- `nfs(5)` nu menționează `_netdev`, `x-systemd.*`, `noexec`, `nosuid`. Din `mount(8)`: `_netdev` = dispozitivul cere rețea (se așteaptă rețeaua); `noexec`/`nosuid`/`nodev` generice; `x-*` este prefix generic stocat în spațiul utilizator (opțiunile `x-systemd.*` nu au fost citite în sursă).
- `exports(5)`: format `cale client(opțiuni)`; `ro` implicit, `rw` permite scrierea; `sync` implicit; `root_squash` implicit (root-ul clientului → utilizator anonim); `no_root_squash`, `all_squash`; `sec=` implicit `sys`; `fsid=0`/`root` = rădăcina NFSv4; „To apply changes to this file, run exportfs -ra or restart the NFS server”; `/etc/exports.d/*.exports` sunt citite și ele.
- `showmount -e host` = lista de exporturi; interoghează daemonul mount al serverului (serviciul MNT); **pe servere doar NFSv4 poate să nu funcționeze**.
- `umount`: `-f` (server inaccesibil; fără garanție), `-l` lazy (pentru rețea poate cere reboot curând), `-t nfs` vs `nfs4` diferă față de fstab.

## Din cunoștințe, necitit în sesiune
- Pachetul client: `nfs-utils`; `mount.nfs`; `systemctl enable --now nfs-server` pentru server (ieșit din obiectiv; doar menționat).
- Port NFSv4: TCP 2049; `firewall-cmd --add-service=nfs` (C8/C10).
- SELinux: booleane `nfs_export_all_rw`/`nfs_export_all_ro` (server), `use_nfs_home_dirs` (client, directoare home pe NFS) — de confirmat nume pe RHEL 10.
- `nfsstat -m`, `findmnt -t nfs,nfs4`, `mountstats` pentru verificare.
- NFSv2 nu mai este suportat; versiuni v3/v4.x — de confirmat pentru RHEL 10 (nu a fost citit nimic).
- Timeout mount NFS: implicit `mount` poate dura mult dacă serverul nu răspunde (`hard`) — comportament standard.

## Nesigurante
- Textul exact al ghidului RHEL 10 „Mounting NFS shares” (comanda `mount -t nfs -o options host:/remote/export /local/directory`) — cunoscut din RHEL 8/9, neconfirmat.
- Versiunile implicite negociate pe RHEL 10 și prezența `nfs.conf` cu `[nfsd]`/`[nfsmount]` (necitit).
- Laboratorul cere un server NFS la dispoziția celui care învață (propriul VM); platforma nu oferă și nu verifică niciunul.
